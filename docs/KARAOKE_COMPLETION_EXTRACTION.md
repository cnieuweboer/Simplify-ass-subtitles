# Karaoke completion — v238

The complete operation assessed in
[KARAOKE_COMPLETION_EXTRACTION_ASSESSMENT.md](KARAOKE_COMPLETION_EXTRACTION_ASSESSMENT.md)
now lives in `_simplify_ass/karaoke_completion.py`: thirteen functions and two
existing frozen records, totaling 215 definition lines. All fifteen definition
ASTs are unchanged. Engine names remain direct aliases, preserving signatures,
canonical record identity, shallow freezing and historical root pickle lookup.
The runtime version is `2026.10.20.238`.

## Responsibility and ownership

The module owns retained-row matching, source-phase coverage, transition and
ordered-sweep proof, and destination-paint replacement. Both the original-source
and supplied-outline-profile routes retain their existing conditions, timing
bounds, continuation handling, paint fields and conservative refusal behavior.

Working/source events, visibility, supplied profiles and their paint dictionaries
remain borrowed. Row buckets, filtered source indexes, phase/hold lists and
replacement maps remain call-local. No persistent cache, diagnostic owner or
resource abstraction is introduced. The two records remain frozen without
copying or freezing their mutable contents.

The outline-strip producer remains in the engine: it retains geometry, palette,
compositing, fade and contrast proof before discarded copies become unavailable.
It constructs the canonical shared profile. `flatten_stacked_text_copies()` still
invokes completion before its glow-boundary handoff;
`_finish_text_effect_sequences()` still invokes it after moving-glyph reduction
and before exact-position consolidation. Both callers retain source selection,
stage conditions, aggregate accounting and reporting. There is no new counter.

Paint successors preserve geometry, timing, flags, measurement context and
source IDs; untouched events retain identity and list order. No-candidate input
returns its original list, while candidate processing retains its existing
new-list behavior even when every proof refuses. An absent profile map still
selects source reconstruction; an empty supplied map does not. Repeated direct
normalization retains stable resolved paint and its existing redundant-tag
spelling; the later compaction boundary is unchanged.

The module depends on eight established private owners plus the standard library.
The import graph is acyclic, with no engine import, callback adapter or runtime
forwarding for tests. No font handles or path-sensitive code move. Cold import
and both font-independent proof routes run before the engine or optional font
backends are imported.

outline producer still owns its evidence, and both consumers use the canonical
records and existing successor editor. No preparatory production change,
workaround, duplicated proof, local exception or downstream repair was needed.
